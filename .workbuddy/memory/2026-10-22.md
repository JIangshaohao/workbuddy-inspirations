## 新增灵感 `ai-query-hero-landing`

- 需求：一份 HERO SECTION 规格（React 组件描述风格：全屏视频背景 + 自研 JS 淡入淡出系统 + 导航 + 徽章 + 大标题 + 毛玻璃搜索卡），主文案 "Transform Data Quickly"。用户要求「新建一个文件夹制作，不要影响其他文件夹中的内容」→ 独立目录 `ai-query-hero-landing/`，未改动任何已有灵感。
- 与本仓库既有灵感同路：规格虽是 React 组件描述，按用户一贯偏好实现为**纯静态单文件** `index.html`（Tailwind Play CDN + Google Fonts + 内联 SVG 图标 + 原生 JS）。
- 视频淡入淡出按规格实现为纯 rAF（无 CSS transition）：`fadeTo()` 从当前 opacity 出发渐变、新动画先 `cancelAnimationFrame` 旧帧、`timeupdate` 检测距结尾 ≤0.55s 触发淡出（`fadingOut` 标志位防重复）、`ended` 归零 → 100ms → `currentTime=0` 重播 → 再淡入。
- 踩坑一：**Tailwind preflight 的 `img, video { max-width: 100% }` 会把 `width: 115%` 压成 100%**（实测 1440px 而非 1656px）。解法：写 `.hero-video.hero-video` 双类名提高特异性压制 preflight。
- 踩坑二：CDP 脚本 `Page.navigate` 后立即 `Runtime.evaluate` 会拿到 `undefined`（执行上下文已销毁）；需先等 `document.readyState === 'complete'` 再等 `video.readyState >= 2`（15MB 外链视频约 20s 解首帧）。
- 踩坑三：`querySelector` 里拼 Tailwind 任意值类名（`w-[82px]`）会因 `#` `[]` 转义出错而整条选择器失效 → 改为给被断言元素加语义化 id，验收脚本只用 id 选择器。
- 踩坑四（环境限制，非实现缺陷）：headless 中把 `currentTime` seek 到接近结尾会卡在缓冲态，`timeupdate` 事件数为 0、视频时间不前进，无法用真实时间轴验证淡入淡出。改用**确定性测试**：页面内 `Object.defineProperty` 在实例上覆盖 `duration`/`currentTime` 遮蔽原型只读 getter，手动派发 `timeupdate`/`ended` 做断言，`tools/verify-fade.js` 6 项全通过。
- 规格外补的一处必要修正：`ended` 分支先 `cancelFade()` 再写 `opacity='0'`，否则仍在跑的淡出帧会覆盖归零效果（对应规格「Each new fade cancels running animation frames」）。
- 移动端：120px 固定横向内边距在 390px 宽下把内容挤到 150px 并溢出 → 改为 `px-6 sm:px-10 lg:px-[120px]`，标题 `lg` 以下降到 40/56px；桌面端数值仍严格等于规格。
- 三件套与根 README / MEMORY 索引已同步追加。
