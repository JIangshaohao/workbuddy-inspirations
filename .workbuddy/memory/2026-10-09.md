**做了什么**

- 以参考实现 `.../code-colorharbor-palette/output.html` 为审美基线，按需求补齐三处偏差：分类标签与随机按钮**同处一行**、收藏入口移到页头右侧、收藏爱心移到色块**右下角**。
- 配色数据 24 → **30 组**（5 类各 6 组），类别标签中文化、配色名保留英文。
- 质量升级 1：新增 `idealText()`（自动黑/白字）+ `readable()`（保色相向白提亮），修掉预览区用极暗色（`#03045E` / `#001F3F`）导致文字与描边隐形的问题；色块本体仍显示真实色值。

- 卡片高度改为由 id 哈希预计算并缓存（`p.h`），过滤重渲染不再跳动。

**关键技术结论（已写入项目 MEMORY.md）**

- **`animation-fill-mode: both` 会永久钉住结束帧的 `transform`**，直接压制 `.color-block:hover{ transform: scale() }`。改用 `backwards`：结束后 transform 交还样式表。（参考实现里就埋着这个问题）
- **深色面板上的预览色必须做对比度提亮**：配色库的 UI 预览直接拿配色深色当文字色，接近黑就完全不可读。
- **详情浮层要 `opacity + visibility` 双切换**，只切 `opacity` 会让隐藏态仍可被 Tab 聚焦。
- **无头截图校验的坑**：CSS 过渡在 headless `--virtual-time-budget` 下不一定推进到终态，截图会抓到动画中途（内容半透明/缺元素），而 `--dump-dom` 证明 DOM 正常。定位顺序＝先 dump-dom 排除真实缺陷，再冻结 `transition/opacity/transform` 或加 `--force-prefers-reduced-motion` 取终态图。
- **别靠肉眼判断 computed style**：一度以为 `--star` 没传递（截图中星星是红的），实为 `Sunset Gold` 的 `colors[4]` 本就是 `#B22222`；用注入脚本 + `getComputedStyle` 打点才排除。

**校验结果**：内联 JS 通过 `node --check`；无头 Chrome 实测首屏渲染 30 张卡片 / 6 个分类标签 / 30 个爱心按钮；详情态与收藏抽屉终态截图均正常。

## 新增灵感：`netmusic-listening-portrait`（网易云音乐「你的听歌画像」）

**交付物**：`netmusic-listening-portrait/index.html` —— 单文件数据可视化长页报告（约 197 KB，图片全 base64 内联，零外链）。
配套三件套已建，根 `MEMORY.md` 灵感索引已追加。

**需求**：用真实听歌数据生成个人听歌报告，深色沉浸 / 音乐杂志风，静态预渲染、不依赖 JS 注入、响应式、手机可看。
用户实际主力是**网易云音乐**（酷狗技能仅为参考），并主动询问如何接入。

**联通方案（关键结论）**：网易云**没有官方连接器**，官方开放平台需企业资质且不开放个人听歌历史。
落地路径＝本地跑开源 `NeteaseCloudMusicApi`（npm v4.32.0）+ **扫码登录**（`login_qr_key` → `login_qr_create` 出二维码 → `login_qr_check` 轮询）。
凭证只落本地 `.workbuddy/tmp/netease-api/cookie.json`。

**做了什么**

- 数据拉取：`user_account` / `user_subcount` / `user_playlist` / `likelist` / `playlist_track_all`（分页）×  `user_record`（`type=0` 全部时间、`type=1` 最近一周）/ `song_detail`（补 `publishTime` 做年代分析）。
- 实测规模：收藏 **4,737** 首、自建歌单 **24** 个、订阅歌单 **17** 个、注册 2017-12-04。
- 8 个章节：Hero 一句话画像 → 核心数字 → 常听歌曲与歌手 → 曲风偏好 → 收藏×实际播放 → 陪伴最久×最近靠近 → 音乐坐标 → 听歌方式 → 阶段总结。
- 图表全部为**构建期生成的内联 SVG**：分组柱状图 ×2、收藏云散点 ×1；Hero 为 AI 生成的唱片机特写（裁掉底部 8% 水印 + JPEG q76 → 73KB）。
- 页面运行时零数据依赖；`.reveal` 淡入仅在 `html.js` 下生效，JS 失效仍完整可读。

**报告的核心发现（叙事立论）**

- 历史播放 Top100 **100% 来自他自己的收藏**——只吃自己囤的粮；4,737 首里仅 100 首进入高频回放（2.11%，47:1）。
- 全部时间 Top100 与最近一周 Top100 **零重叠**：长期是 Ólafur Arnalds / 巫师3 OST / 新古典器乐，近期转向 Gigi Perez / MJ / Backstreet Boys 的千禧年 R&B。
- 老歌转向可量化：本周 27% 播放来自 2009 年前，历史总榜仅 6%，**相差 4.6 倍**。
- 「囤而不听」名单：邓紫棋 32、薛之谦 30、陈奕迅 25、张学友 25、林俊杰 22、孙燕姿 18、李荣浩 18。

**关键技术结论（已写入项目 MEMORY.md）**

- `user_playlist` 的 `specialType: 0` **混装自建与订阅歌单**，必须用 `subscribed` 字段区分，否则「自建歌单数」算错。
- 歌手榜必须按**主要艺人 `ar[0]`** 归并，否则古典专辑的弦乐演奏者会各占一席污染榜单。
- 散点图改用「收藏云 + 已播高亮」：原设计纵轴（热度）被压扁失效；云用 `<path>` 小线段（每点约 11 字符，4,220 点约 46KB），比几千个 `<circle>`（约 300KB）省一个数量级。
- **超长单页截图不能用 `chrome --screenshot`**（只截视口，且 `svh` 会把 Hero 撑满超长窗口）。改用 CDP：`Emulation.setDeviceMetricsOverride` + `Page.captureScreenshot({captureBeyondViewport:true, clip})`；Node 22 自带 `WebSocket`，零依赖。横向溢出同样用 CDP `Runtime.evaluate` 实测（结论：无溢出，肉眼误判）。
